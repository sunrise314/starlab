# StarLab 实战（六）：205 个同频邻居，C/I 是负的

## 一、那个 null 今天开工

第 5 章的基准代码里有一行我特意留了伏笔：`new SimulationEngine(constellation, prop, links, null, greedy)`——第四个参数 `InterferenceCalculator` 传了 `null`。这个类是 v3 干扰模型的物理内核，Walker 12 星时代就写好了，但从来没在真实星座上跑过一次。第 5 章结尾预告的三个问题，就是它的开工任务：

- 751 颗同时在线的卫星共享同一段频谱，每个地面站头顶有多少个同频邻居？
- 可见链路的载干比 C/I 能跑到多少？离"能解调"的 9 dB 门限差多远？
- 干扰感知策略（v3）能不能在 Greedy 和 Predictive 之外杀出第三条路？

我把 10681 颗真 Starlink 卫星灌进干扰模型，扫了 2 小时、1200 个时刻×站组合、24.7 万条可见链路。先剧透判决：**没有一条链路的 C/I 过了门限，连最好的一颗也差着 25 分贝。** 这一章讲清楚这个数字是怎么来的、意味着什么，以及 v3 策略的"第三条路"为什么被数据证伪。

## 二、单信道假设：干扰模型的三笔账

`InterferenceCalculator.analyze()` 对每条"目标卫星—地面站"链路算三笔账：

```java
for (SatellitePosition sat : allSats) {
    if (sat.satelliteId().equals(targetSat.satelliteId())) continue;
    LinkResult iLink = linkCalculator.calculate(sat, station);
    if (!iLink.visible()) continue;                    // 不可见的卫星不构成干扰
    double iDbm = linkCalculator.receivedPowerDbm(iLink);
    coChannelPowerMw += dbmToMw(iDbm);                 // 同频：功率全额进接收带宽
    aciPowerMw += dbmToMw(iDbm - ACI_ISOLATION_DB);    // 邻信道：被 30dB 隔离度抑制
}
double cirDb = carrierDbm - mwToDbm(co + aci + noise); // C/I = C − 10·log10(ΣI + N)
```

同频干扰按非相干功率线性求和，邻信道泄漏被 ACIR（邻信道隔离度 30 dB）压低 1000 倍再加进来，最后加上接收机噪声底 N = −174 + 10·log10(20MHz) + NF(3dB) = **−98 dBm**。链路可用性的判据是三条件与：可见，且 C/I > 9 dB（QPSK 1/2 的解调下限加余量），且 SNR > 3 dB。

这里必须把模型最大的假设摆在明面上：**全星座共享同一个 20 MHz 信道。** 每颗可见卫星的下行信号都全额落进每个站的接收带宽，没有波束隔离、没有频率规划、没有极化复用。这是最保守的下界——它回答的问题是"如果什么都不做，频谱会挤成什么样"。这个假设是本章全部戏剧性的来源，也是第 7 章要动手改造的对象。

## 三、205 个同频邻居

第一个问题：每个站的头顶上到底有几个干扰源。普查口径是第 5 章的同款——T0 起步、2 小时、30 秒一个 tick，共 240 个时刻 × 5 个站 = 1200 个"时刻×站"采样，每个采样里数一遍仰角 ≥10° 的可见卫星数 K：

| 分位数 | min | p10 | 中位 | 均值 | p90 | p99 | max |
|--------|-----|-----|------|------|-----|-----|-----|
| K（个/站） | 141 | 161 | **205** | 205.9 | 249 | 265 | 281 |

各站平均值：北京 247、喀什 227、上海 205、漠河 191、三亚 160。

教科书做干扰分析，例题里的同频干扰源通常是一到六个；工程手册给的复用因子折算下来也是个位数。**真实星座给的是 205。** 任一时刻，每个中国地面站的接收机里挤着两百多个同频发射机，它们不排队、不让路，功率直接相加。

这组数字还能和第 5 章交叉验证：751 颗可见卫星，平均每颗能看到 1.37 个站（可见星对中国五站的空间重叠），得到约 1030 个可见"星-站"对，摊到 5 个站正好每站 206 个——两个独立口径（第 5 章的在线率快照 vs 本章的干扰源普查）又一次咬合。数字之间能互相咬合，才敢写进结论。

## 四、C/I 崩塌

第二个问题是本章的核心判决。24.7 万条可见链路（1200 采样 × 平均 206 条/采样）的 C/I 分布：

| 口径 | p10 | 中位 | p99 | max | ≥9 dB 比例 |
|------|-----|------|-----|-----|------------|
| 全部可见链路 | −28.3 | **−25.2** | −16.4 | −10.5 | **0.0000%** |
| 每"时刻×站"里最好的一颗 | −17.2 | −15.8 | −12.3 | −10.5 | 0.0000% |

**中位数是负 25 分贝，全场最大值是负 10.5 分贝，没有一条链路能解调。** 更扎心的是"选最好"的收益：从全部链路到每站最优，中位 C/I 只抬了 9.4 dB（−25.2 → −15.8），而离门限还差 24.8 dB。挑出天顶上那颗最强的星，也只够把差距从"绝望"缩到"依然绝望"。

和 SNR 对照着看更有意思。同一条链路、同一时刻，不考虑干扰只算热噪声的 SNR 中位数是 **29.9 dB**——按链路预算的标准，这是"随手跑 Shannon、吞吐拉满"的健康链路。两套口径的差值就是干扰的账：

```
SNR（只看噪声）  中位 +29.9 dB   → 噪声底 −98 dBm
C/I（加上同频）  中位 −25.2 dB   → 干扰合计 ≈ −43 dBm
干扰合计高出噪声底：中位 55.1 dB（min 53.1，max 56.7）
```

29.9 − 55.1 = −25.2，两个独立口径严格自洽。这个系统**根本不是噪声受限，是干扰受限**——把接收机噪声系数做到 0 dB、把天线增益翻倍，都改变不了任何事，因为压垮链路的是同频邻居的功率和，不是热噪声。

那分频能救吗？算一笔账：要让中位链路的 C/I 从 −25.2 抬到 9 dB，需要把干扰摊薄 34.2 dB，即 10^3.42 ≈ **2624 个正交信道**。20 MHz 分给 2624 份，每份 7.6 kHz——L 频段总共都没这么宽。分频这条路的数学尽头在这里，唯一的出路是空分：让天线只看该看的方向。这正是第 7 章的主题，也是真实 Starlink 相控阵存在的理由。

## 五、O(N²) 的账单与一次摊平

跑这组数字之前，v3 策略先给我上了一课——关于计算复杂度。

生产版 `InterferenceAwareHandoverStrategy` 的每次决策都要：把**全星座 10681 颗卫星重新传播一遍**（枚举干扰源），再对每个可见候选站做一次全星座干扰扫描。12 星时代这是每星每 tick 一百来次链路计算，无感；万星时代实测单次决策 **2.9 ms**，一次 2 小时仿真要调用 240 tick × 10681 星 ≈ 256 万次——**总计约 2.1 小时，比仿真本身的时长还长**，实时率 0.5 倍。O(N²) 不是抽象概念，是一张按小时计费的账单。

处理方式是经典的"每 tick 摊平一次"：同一时刻所有卫星共享同一份干扰格局，那就每个 tick 只做一次全星座扫描（实测 14 ms），把每个站可见卫星的功率合计 S_co、S_aci 算好缓存；之后每次选站变成 O(可见站数) 的查表——目标星的 C 就是它自己的接收功率，干扰合计减去它自己的贡献即可。三次方变一次方，2.1 小时压到几秒，全部三方仿真的总耗时 18 秒。

但快没有用，**先得证明快版和原版是同一个算法**。这里复用了第 3 章的黄金数据方法论：抽 12 颗卫星 × 3 种"当前站"状态 = 36 次决策，生产版与快速版逐位对齐——36/36 选站结果与切换原因完全一致，C/I 最大偏差 0.0000 dB。任何"等价实现"在通过逐位校验之前，都只是"另一个碰巧很像的算法"。

## 六、三方对决，以及会骗人的事件流

正赛：同一份星库、同一个起点、2 小时、30 秒 tick，三种策略各自跑完整仿真。

| 指标 | Greedy | Predictive | Interference-aware (v3) |
|------|--------|------------|--------------------------|
| 引擎事件流 | 18262 | 18197 | **11903** |
| 事件构成 | 断链 11903 + 仰角切换 6359 | 预判 3806 + 被动 2638 + 断链 11753 | **断链 11903，仅此一项** |
| 事件流里的每站承接 | SHO 2744 / BJO 1550 / MHO 1553 / SYO 512 | SHO 2614 / BJO 1830 / MHO 1545 / SYO 455 | **空** |
| 平均切换时延 | 12.6 ms | 12.1 ms | 0.0 ms |
| LINK_BREAK | 11903 | 11753 | 11903 |

报表拉出来第一眼：v3 两个小时"零切换、零时延、每站承接为空"。**三个数字全是假的。** 原因在引擎的事件口径：`simulate()` 只把 `ELEVATION_SWITCH` 和 `PREDICTIVE_SWITCH` 记为事件，而 v3 的决策路径走的是 `INTERFERENCE_SWITCH`（当前站 C/I 跌破门限强制改站）和 `LINK_BREAK`（当前站不可见重连）两个静默通道——它们直接更新服务站映射，不产生任何事件。口径没跟上决策路径，报表就是一幅抽象画。

真相在策略内置的决策账本里：

```
reason 分布（共 256 万次决策调用）：
  NO_VISIBLE          2,372,557   ← 93% 的卫星此刻无站可见，无事可做
  NONE                  159,681   ← 最优站就是当前站，按兵不动
  INITIAL                12,651   ← 首次接入
  INTERFERENCE_SWITCH     6,183   ← 静默：C/I 恶化，强制改站
  LINK_BREAK(reason)        557   ← 静默：当前站没了，重连别站
  ELEVATION_SWITCH             0   ← 两站 C/I 都 ≥9dB 才走这条，从未发生
```

**v3 的真实站间倒手是 6183 + 557 = 6740 次**——和 greedy 的 6359、predictive 的 6444 在同一量级。真实每站承接：上海 3025、漠河 1656、北京 1490、三亚 569，和 greedy 的负载结构（SHO 2744 / MHO 1553 / BJO 1550 / SYO 512）几乎同构。顺带一提，12651 次首次接入里有 4890 次（39%）落在喀什——新卫星大多从西边升起，先过中国最西的喀什上空，首见站即仰角最高站。这是几何，不是 v3 的功劳，greedy 同理。

所以，第三条路存在吗？**不存在。** 原因不在实现，在数学：某站的干扰合计由该站全部可见卫星决定，与你给目标星选哪个站几乎无关；C/I 排序退化为 C 排序，C 排序就是仰角排序。v3 精心计算的"最高 C/I 站"，和 greedy 无脑选的"最高仰角站"是同一个答案，外加 2 dB 滞后环带里的少量扰动。干扰感知策略要有意义，前提是干扰在候选之间**有区分度**——而这恰恰是频率规划和波束隔离该干的活。先造出异构的干扰格局，"感知"才有东西可感知。

## 七、工程教训

**先验证决策空间的区分度，再上算法。** C/I 在五个站之间的差异只有约 2 dB（邻居数 247 vs 160，折算 1.9 dB），而缺口是 25 dB。目标函数在候选间几乎平坦时，一切"智能选优"都是同一个词的不同拼法。判断方法也简单：把目标函数的候选间极差和问题阈值摆在一起看一眼——9.4 dB 的选择收益对 24.8 dB 的缺口，一眼假。

**统计口径必须跟着决策路径走。** 引擎记录三类事件，v3 走两个静默通道，于是报表同时给出"零切换、零时延、零承接"三个假象。账本要埋在决策产生的地方（策略内部计数器），而不是假设所有决策都汇入同一条事件流。这次是我自己的引擎埋的坑——生产代码里同样的坑只会更隐蔽。

**复杂度按目标规模设计，不按演示规模。** O(N²)/tick 在 12 星时代是每 tick 一百多次计算，在万星时代是每 tick 1.1 亿次。算法从 demo 走向真实规模之前，先算一遍"如果 N ×1000 会怎样"；凡是不依赖逐对组合的状态（这里是"每站干扰合计"），都应该摊平成每 tick 一次。以及永远记得：等价优化必须先过逐位校验，否则你测的是另一个算法的性能。

## 八、预设追问清单

1. 单信道假设公平吗？——对"什么都不做"的场景它是自洽的下界；真实系统靠波束成形、极化、频率规划拿到 20~30 dB 起步的空间隔离。但注意，这恰恰是本章结论的另一面：那些手段不是"优化项"，是整个系统能运转的前提；
2. 为什么最好的一颗也差 25 dB？——干扰合计 ≈ −43 dBm 由 205 个邻居的功率和决定（205 个就白送 23.1 dB 的相加增益），天顶星 C ≈ −60 dBm 也压不过功率和；
3. 55 dB 这个数怎么理解？——干扰合计与噪声底的比值：205 个 −70 dBm 量级的信号相加约 −43 dBm，对 −98 dBm 的噪声底就是 55 dB。这意味着接收机里同频功率是热噪声的三十多万倍；
4. v3 的负载为什么还是上海最重？——C/I = C − I，I 的站间差只有约 2 dB，C 的站间差（仰角/斜距）有几 dB 且方向性更强；仰角排序主导选站，上海依然是几何上的倒手枢纽，第 5 章的结构性结论不变；
5. 2624 个信道意味着什么？——需要 34.2 dB 的干扰摊薄，折合 2624 个正交信道，每个只有 7.6 kHz；这条数学上的死路说明分频救不了 LEO 星座，必须空分；
6. 事件流为什么会漏掉切换？——引擎只把两类 reason 映射为事件，v3 的决策原因不在这两类里；修引擎是代码问题，本章选择"账本+事件流双口径"呈现，因为对比新旧策略时口径差异本身就是结论的一部分；
7. 如果把干扰源限制成"只有同倾角壳的卫星"呢？——那是最朴素的一档频率复用（按壳分信道），C/I 能抬多少、离 9 dB 还差多少，正是第 7 章的第一组实验。

## 九、下一章预告（星球专属）

第 7 章：**把频谱预算补上——频率复用实验。** 单信道下 C/I 无解，那就改规则：按倾角壳分信道、按轨道面分组、极化隔离，每加一档隔离度，C/I 中位数抬多少、离 9 dB 门限还差几步——用同一套基准量化回答"Starlink 到底靠什么活下来"，以及相控阵波束的空间隔离为什么不是锦上添花，而是生死线。
