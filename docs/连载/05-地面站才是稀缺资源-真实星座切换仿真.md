# StarLab 实战（五）：7% 的在线率，Greedy 与 Predictive 的真实对决

## 一、Walker 12 星给不了的真实感

前三章搭切换仿真的时候，星座是 Walker 12/3/1——12 颗虚拟卫星绕着 5 个地面站转。那个世界很温和：12 颗星均匀铺开，几乎总有一站在服务区内，切换是"锦上添花"的优化问题，Greedy 和 Predictive 的差异体现在过境尾段那几十秒的抖动上。

第 4 章末尾留下的承诺，是把 10681 颗真 Starlink 卫星整体灌进这个仿真。灌进来之后第一件事就是重跑切换对比，然后我发现教科书叙事在真实星座面前碎了一地：

**切换策略根本不是这个故事的主角。** 在 10681 颗真卫星、5 个中国地面站的真实拓扑下，任意时刻全星座只有约 7% 的卫星能看到至少一个站。剩下 93% 的卫星此刻在太平洋上空、大西洋上空、或者干脆在地球背面——它们不是"排队等待切换"，是根本无事可做。真正的稀缺资源从来不是卫星，是地面站的视野。

这一章把三组实测数字摆出来：倾角壳的可见性普查、单时刻的在线率快照、Greedy 与 Predictive 的 2 小时对决。所有数字来自同一个基准测试 `HandoverBenchmarkTest`，跑一遍 20 秒。

## 二、一把能打的尺子：基准怎么搭

先交代方法，数字才可信。基准测试的装配只用了三步：

```java
Constellation constellation = new Constellation();   // 默认 Walker 12 星
constellation.replaceSatellites(cat.satellites());   // 真实星库整体换装（第 4 章的管道）

// 干扰计算器传 null：compare() 不用它，第 6 章再请回来
SimulationEngine engine = new SimulationEngine(
        constellation, prop, links, null,
        new GreedyHandoverStrategy(constellation, prop, links));

CompareResult cmp = engine.compare(greedy, predictive, T0, 7200, 30);
```

可见性普查的口径：以 TLE 历元邻近的 `2026-10-03T12:00:00Z` 为起点，扫 100 分钟（略大于 Starlink 的 95.6 分钟轨道周期，保证每颗星的轨道相位被完整覆盖），30 秒一个采样点。每颗卫星 201 个采样点 × 5 个站，全星座合计约 **215 万次轨道传播 + 1075 万次星地链路计算**。

这笔账在第 4 章就埋好了伏笔：SGP4-lite 单颗单步 0.4 µs，链路计算是纯算术。1075 万次链路预算（ENU 变换 + FSPL + 雨衰 + Shannon）在 JIT 预热后，**整个基准跑完 20 秒**——其中切换仿真本体只占 17 秒。万级星座的全量统计实验，成本已经低到"改个参数顺手重跑"的程度，这是性能工作换来的研究自由度。

还有一个小细节值得交代：`compare()` 里 Greedy 和 Predictive 各跑一遍完整仿真，`InterferenceCalculator` 传了 `null`。这不是偷懒——切换仿真只消费 `LinkResult` 的几何与可见性字段，干扰分析是 v3 策略的输入，两件事解耦得足够干净，`null` 就是合法的"暂不参与"。

## 三、10° 是谁的 10°：仰角门限与大气折射

可见性判定长这样（`LinkCalculator` 第 4~5 步）：

```java
// 仰角 = arcsin(U / |Δr|)  —— ENU 变换后的几何仰角
double elevation = Math.toDegrees(Math.asin(up / range));
boolean visible = elevation >= Math.toDegrees(SimConstants.MIN_ELEVATION_RAD); // 10°
```

门限为什么是 10°？5° 以下，大气气体吸收按 `0.3/sin(e)` 急剧放大，多径和地形遮挡也开始捣乱；25° 以上，单次过境的可用窗口会被砍掉一半以上。10° 是信关站设计的行业惯例——Starlink 的用户终端门限更高（25°），因为用户站要考虑房檐和树。

但"几何仰角 ≥ 10°"这个判定，有一个教科书很少较真的偏差：**大气折射**。电波穿过对流层时会被折射弯向地面，从天线看出去，卫星的"视在仰角"比几何仰角高。用 ITU-R P.834 的简化模型（Ns=315 的标准大气）：

```
Δe ≈ Ns × 10⁻⁶ × cot(e)
10° → +0.10°    5° → +0.21°    2° → +0.52°    1° 以下发散，经验限幅 +0.65°
```

这是本次的补强 commit：`LinkCalculator` 新增 `refractionCorrectionDeg`，输出仰角改为视在仰角，可见性判定随之升级——门限是天线看的方向，不是几何方向。

值不值得？实测说话：补强前后全星座在线率从 6.97% 涨到 7.03%，53° 壳单周期零可见从 2151 颗降到 2147 颗。**统计上不显著，语义上必须改**——0.1° 的折射在过境尾段白送 20~30 秒可见时间，而真实天线本来就指着视在方向。写仿真的人最容易在这里犯的错不是"忘了折射"，而是"知道折射却用显著性来决定要不要建模"：正确性不靠效应量投票。

## 四、倾角壳的"不可见时间窗"

重头戏来了。10681 颗卫星按倾角分壳普查（100 分钟窗口、10° 门限、折射修正后）：

| 壳 | 卫星数 | 单周期零可见 | 平均可见 | 中位可见 | 最长可见 | 北京 | 上海 | 三亚 | 喀什 | 漠河 |
|--------|--------|--------------|----------|----------|----------|------|------|------|------|------|
| 53° | 4996 | **2147（43%）** | 395s | 450s | 1080s | 2068 | 1264 | 1045 | 1978 | 1645 |
| 97.6° | 1360 | 222（16%） | 547s | 570s | 1380s | 708 | 599 | 622 | **350** | 751 |
| 70° | 709 | 264（37%） | 384s | 360s | 1170s | 201 | 182 | 154 | 169 | 296 |
| 43° | 3616 | **1633（45%）** | 416s | 420s | 1140s | 1338 | 1597 | 1020 | 1349 | 630 |

右列五站数字的含义：该壳中对**至少一个采样点**可见于该站的卫星数。三个反直觉的发现：

**第一，53° 壳有 43% 的卫星，在任意一个 100 分钟周期里对中国五站全程零接触。** 53° 倾角的星下点纬度范围是 ±53°，三亚到漠河全在这个带里——纬度上"够得着"，但轨道面的相位分布决定了过境时机：一个壳几十个轨道面，面与面之间的经度间隔均匀铺满全球，任一时刻大部分面正对着太平洋和别的大洲。这不是部署缺陷，是几何宿命。

第二，**漠河主要由 53° 壳照顾（1645 颗），43° 壳只有 630 颗的"擦边球"**。43° 壳的星下点最北到 43°N，漠河在 53.5°N——按几何门限 0° 算，卫星距漠河最近也有 10.5° 中心角；换算成 550 km 高度的仰角，封顶约 19°，多数过境是 10~15° 的贴地掠射。低仰角意味着长斜距、高路径损耗、低过境时长。教科书画覆盖图时用"星下点轨迹落进覆盖带"判定，实测告诉我们：**落进覆盖带和能用好是两回事**。

第三，**97.6° 极轨壳对喀什的可见数只有 350 颗，五站最低**。极轨卫星过两极密度最高，赤道带次之，中纬度反而稀；喀什又偏在中国最西（75.9°E），过境窗口比东部站更窄。但极轨壳的单周期平均可见时长（547s）反而是全场最高——一旦遇上，就是一次深的、长的过境。稀疏但优质，这是极轨壳的性格。

还要给这组数字一个诚实的边界：100 分钟窗口只覆盖一个轨道周期，"零可见"不等于"永久不可见"——地球自转让星下点轨迹每个周期西移约 22.5°，多周期会轮转过来。但对一个 100 分钟的运营时段而言，这就是实打实的容量：**四成卫星帮不上忙**。

## 五、此刻，天上有几颗星在看你

第二个快照把时间轴压缩到一瞬。T0 时刻全星座 10681 颗星做一次全量链路计算：

```
可见卫星（对任一站仰角≥10°）：751 / 10681   （7.03%）
五站可用性：BJO=Y  SHO=Y  SYO=Y  KSO=Y  MHO=Y
当前最高仰角：87.8°（有一颗星几乎正过头顶）
```

7.03% 这个数字可以和普查数据交叉验证：全星座单周期平均可见时长约 420 秒，轨道周期 95.6 分钟即 5736 秒，占空比 420/5736 ≈ 7.3%——两个完全独立的口径（时间轴普查 vs 单时刻快照）落在同一个数上，这比任何单一数字都可信。

这个比例就是所有切换策略的物理底座。10681 颗卫星听起来阵容豪华，但"能接住中国五站流量的"永远只有那 751 颗上下。切换算法的全部工作空间，就是这 7%：它们进站、过顶、离站，站间来回倒手。**在真实星座上做切换研究，第一步是接受"在线率是个位数百分比"这个事实——它直接决定了你测出来的任何指标的分母。**

## 六、Greedy 与 Predictive 的真实对决

正赛开始。同一份星库、同一个起点、2 小时窗口、30 秒 tick，两种策略各自跑一遍完整仿真：

| 指标 | Greedy（贪心最高仰角） | Predictive（预测式窗口优先） |
|--------|------------------------|------------------------------|
| 事件总数 | 18262 | 18197 |
| 站间切换 | 6359（ELEVATION_FALL） | **3806 预判 + 2638 被动** |
| 其中"抢占切换"（旧站仰角≥12° 就被拉走） | **5158（81%）** | —（预判切换天然不抢高仰角站） |
| 断链 LINK_BREAK | 11903 | 11753 |
| 平均切换时延 | 12.6 ms | 12.1 ms |
| 切换率 | 152.2 次/分钟 | 151.6 次/分钟 |
| 每站承接 | SHO 2744 / BJO 1550 / MHO 1553 / SYO 512 | SHO 2614 / BJO 1830 / MHO 1545 / SYO 455 |

三个结论，一个比一个扎心。

**结论一：Predictive 没有降低切换总次数，它改变的是切换的"性质"。** 站间切换总数 6359 vs 6444，几乎持平。但 Greedy 的 6359 次里有 5158 次（81%）发生在旧站仰角还≥12° 的时候——纯粹因为隔壁站仰角暂时更高就被拉走，这是教科书说的"临界区抖动"在真实星座里的放大版。Predictive 把其中 3806 次改写成了主动预判：旧站还没不行，但未来 90 秒的窗口测量说"该走了"，提前布局，从容切换。

**结论二：断链次数几乎不动——因为那是物理，不是算法。** LINK_BREAK 11903 vs 11753，只降了 1.3%。断链的主体是"过境自然结束"：卫星沉到地平线以下，任何策略都无法挽留。平均每 0.6 秒就有一次断链发生在这个系统里。再看事件构成：全部事件中断链占 65%（11903/18262），算法能动手的只有剩下 35% 的站间倒手。这个比例给所有"智能切换算法"泼了一盆冷水：**策略能优化的是站间倒手的时机与质量，链路的生死大半由轨道力学决定。** 切换研究的价值边界，被这组数字画得清清楚楚。

**结论三：负载不均是拓扑决定的，策略改变流向但改变不了结构。** 上海站承接了最多切换（2744/2614），三亚最少（512/455）——上海恰好落在 43°+53° 双壳覆盖的叠加区，三亚只有 18.3°N，对 53° 壳来说太南了。有意思的是 Predictive 把更多切换导向了北京（1830 vs 1550）：预判算法偏爱"未来窗口最长"的站，北京以北正是 53° 壳的核心覆盖区。

## 七、工程教训

这一章没有修大 bug，但有三条教训值得单独立牌。

**算法救不了物理。** Walker 12 星时代 Predictive 的优势体现在过境尾段的从容与稳定，一万颗真星一进来，账面上的断链数字几乎纹丝不动——不是算法退化，是问题尺度变了：断链的统计主体从"临界区抖动"变成了"过境终结"。优化方向要对准问题的主体，而不是自己最熟悉的那个模块。

**采样粒度是设计参数，不是实现细节。** tick=30s 意味着一颗边缘掠过的卫星可能只被看见 1~2 个采样点，贡献一对"接入即断"的事件。粗粒度压低计算成本（20 秒跑完全量），但会把短过境的统计压扁；想看清楚边缘行为，得把 tick 降到 5s，代价是计算量 ×6。粒度的选择取决于你回答的问题："系统级切换率"用 30s 足够，"单次过境的抖动曲线"必须细粒度。

**占空比交叉验证应该是基准测试的标配。** 7.03%（快照）和 7.3%（占空比）互相咬合，说明两个独立实现的口径没有跑偏。单一数字只能"报告"，交叉数字才能"证明"——这一招是从第 3 章的黄金数据方法论里继承来的：任何没有第二个独立来源背书的数字，都别写进结论。

## 八、预设追问清单

1. 为什么扫描窗口是 100 分钟而不是 24 小时？——100 分钟略大于轨道周期，单周期内轨道相位全覆盖且不超出 TLE 历元的可信外推范围；24 小时统计的是多周期轮转的长期平均，是另一个（也值得做的）实验；
2. "43% 零可见"是永久的吗？——不是。地球自转让星下点每周期西移约 22.5°，多周期会轮转进中国经度带；但对单个 100 分钟运营时段，它就是真实的容量缺口；
3. 折射 0.1° 也值得建模？——统计上不显著（在线率 6.97%→7.03%），但"天线指向"的语义就该是视在方向；且模型在 5° 以下影响放大，为将来降低门限的实验预留了正确的基础；
4. 为什么 LINK_BREAK 高达 1.2 万次？——每次过境终结记一次，2 小时内万级过境架次是 7% 在线率的必然；tick=30s 也把部分边缘掠过压成"接入即断"的短事件；
5. Predictive 时延为什么反而略低？——预判切换发生在仰角尚可、候选充裕的时刻，选中的站斜距分布更优；0.5 ms 的差异在传播时延的离散度以内，定性正确即可；
6. 冷却期 60 秒在真实星座下有副作用吗？——有。断链后 60 秒禁止重新选站，对短过境卫星等于放弃本次过境的尾段；12 星时代无感的参数，万星规模下成了可测量的损耗；
7. "接入"是什么粒度？——星到站一对一直连，没有星间激光链路（ISL）和多跳路由；Starlink 真实架构里流量可以沿星间链路绕地球半圈再落地，那里的"切换"是另一个维度的故事。
